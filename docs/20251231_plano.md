## 1. Visão Geral

### Abordagem: Batches Dinâmicos por Container

```
557 APKs → 37 batches (15-16 APKs cada) → 7 containers independentes
```

Cada container processa batches sequencialmente. Quando um container termina seu batch, é reconfigurado para o próximo batch disponível, sem afetar os outros containers.

### Vantagens

- **Sem ociosidade**: Container terminou → pega próximo batch
- **Balanceamento**: Containers rápidos processam mais batches
- **Isolamento**: Reinicia só 1 container, outros continuam
- **Recuperação**: Se travar, afeta apenas 15 APKs
- **Rastreamento**: BATCHES.csv controla alocação

## 4. Preparação Inicial (Uma Vez)

### 4.1. Criar Estrutura de Batches

```bash
# Criar diretórios de batches
for i in $(seq -w 1 37); do
    mkdir -p batches/$i
done

# Copiar APKs para cada batch (usar APKs.csv como referência)
# Script disponível em scripts/prepare_batches.py
```

### 4.2. Criar Estrutura de Containers

```bash
for i in 01 02 03 04 05 06 07; do
    mkdir -p containers/$i/{instrumented,results,specs}
    cp -r specs/* containers/$i/specs/
done
```

### 4.3. Criar .env

```env
REPETITIONS=3
TIMEOUTS=60 120 180 300
TOOLS=ape ares droidbot droidbot_bfs_greedy droidbot_bfs_naive droidbot_dfs_greedy droidmate fastbot humanoid monkey qtesting
HUMANOID_URL=humanoid:50405
NO_WINDOW=true
JCA_SPEC=false
CPUS=8
MEMORY=16g
```

### 4.4. Criar docker-compose.yml

```yaml
services:
  humanoid:
    image: phtcosta/humanoid:1.0
    container_name: rv-humanoid
    ports:
      - 50405:50405

  rv01:
    image: phtcosta/rvandroid:0.0.1
    container_name: rv-01
    environment:
      - RV_REPETITIONS=${REPETITIONS}
      - RV_TIMEOUTS=${TIMEOUTS}
      - RV_TOOLS=${TOOLS}
      - RV_HUMANOID_URL=${HUMANOID_URL}
      - RV_NO_WINDOW=${NO_WINDOW}
      - RV_JCA_SPEC=${JCA_SPEC}
    volumes:
      - ./batches/01:/opt/rvsec/rv-android/apks          # ← Mudar para próximo batch
      - ./containers/01/instrumented:/opt/rvsec/rv-android/out
      - ./containers/01/results:/opt/rvsec/rv-android/results
      - ./containers/01/specs:/opt/rvsec/rvsec/rvsec-mop/src/main/resources/generic
    devices:
      - /dev/kvm:/dev/kvm
    deploy:
      resources:
        limits:
          cpus: ${CPUS}
          memory: ${MEMORY}
    depends_on:
      - humanoid

  # rv02, rv03, rv04, rv05 similar (mudar números)
```

## 7. Quando um Container Termina (100%)

### 7.1. Verificar Conclusão

```bash
# Via monitor
python monitor.py containers --prefix rv

# Ou via logs
docker logs rv-01 2>&1 | grep "Status:" | tail -1
# Status: {'tasks': XXX, 'completed': XXX, 'pct': 100.0}
```

### 7.2. Parar o Container

```bash
BATCH=01
CONTAINER=01

docker stop rv-$CONTAINER
```

### 7.3. Identificar Timestamp

```bash
TIMESTAMP=$(ls containers/$CONTAINER/results/ | grep -E "^[0-9]+$" | head -1)
echo "Timestamp: $TIMESTAMP"
```

### 7.4. Criar Diretório de Resultados

```bash
mkdir -p results/batch-$BATCH
```

### 7.5. Copiar Resultados

```bash
# Copiar diretório de timestamp (resultados de execução)
cp -r containers/$CONTAINER/results/$TIMESTAMP results/batch-$BATCH/

# Salvar log do container
docker logs rv-$CONTAINER > results/batch-$BATCH/execution.log 2>&1

# Copiar erros de instrumentação (se existir)
if [ -f containers/$CONTAINER/instrumented/instrument_errors.json ]; then
    cp containers/$CONTAINER/instrumented/instrument_errors.json results/batch-$BATCH/
fi
```

### 7.6. Criar ZIP

```bash
cd results
zip -r batch-$BATCH.zip batch-$BATCH/
cd ..

# Verificar
ls -lh results/batch-$BATCH.zip
```

### 7.7. Atualizar BATCHES.csv (Batch Concluído)

```csv
01,15,5,01,completed,2026-01-01 11:44,2026-01-02 14:30
```

### 7.8. Limpar Container

```bash
rm -rf containers/$CONTAINER/results/*
rm -rf containers/$CONTAINER/instrumented/*
```

### 7.9. Configurar Próximo Batch

Editar docker-compose.yml:
```yaml
  rv01:
    # ...
    volumes:
      - ./batches/08:/opt/rvsec/rv-android/apks    # ← Próximo batch disponível
```

**IMPORTANTE**: Se o container tinha config de resume, remover:
```yaml
    environment:
      # REMOVER estas linhas:
      # - RV_MEMORY_FILE=...
      # - RV_SKIP_INSTRUMENT=true
      # - RV_SKIP_MONITORS=true
      # - RV_SKIP_STATIC_ANALYSIS=true
```

### 7.10. Atualizar BATCHES.csv (Novo Batch)

```csv
08,15,8,01,running,2026-01-02 14:35,
```

### 7.11. Reiniciar Container

```bash
docker compose up -d rv$CONTAINER
```

### 7.12. Verificar Início

```bash
docker logs rv-$CONTAINER 2>&1 | head -20
```

## 8. Resume (Container Travado)

> **NOTA**: O watchdog.py automatiza este processo. Executar apenas se o watchdog não estiver rodando.

### 8.1. Diagnosticar

```bash
# Verificar se está travado (0 = travado)
docker logs rv-01 --since 5m 2>&1 | wc -l

# Verificar zombies
docker exec rv-01 ps aux | grep "emulator.*defunct"

# Verificar CPU baixa
docker stats --no-stream rv-01
```

### 8.2. Parar Container

```bash
docker stop rv-01
```

### 8.3. Identificar Timestamp

```bash
CONTAINER=01
TIMESTAMP=$(ls containers/$CONTAINER/results/ | grep -E "^[0-9]+$" | head -1)
echo "Timestamp: $TIMESTAMP"
```

### 8.4. Configurar Resume

Editar docker-compose.yml, adicionar na seção environment:
```yaml
  rv01:
    environment:
      # ... variáveis existentes ...
      # Resume config
      - RV_MEMORY_FILE=/opt/rvsec/rv-android/results/$TIMESTAMP/execution_memory.json
      - RV_SKIP_INSTRUMENT=true
      - RV_SKIP_MONITORS=true
      - RV_SKIP_STATIC_ANALYSIS=true
```

### 8.5. Recriar Container

**IMPORTANTE**: Sempre recriar o container do zero, não apenas reiniciar. Usar `docker compose up -d` sozinho pode não funcionar corretamente (emulador não inicia, fica com CPU/RAM baixos).

```bash
docker stop rv-01 && docker rm rv-01 && docker compose up -d rv01
```

### 8.6. Verificar Resume

```bash
# Deve mostrar mensagens "Skipping already executed task"
docker logs rv-01 2>&1 | grep "Skipping" | head -5
```
